## Encoding, Hashing, and Encryption

There are a few approaches to protect data by converting it to some other format: including encoding, hashing, and encryption.

| **Encoding**                                                                                                                                           | **Encryption**                                                                                                                                                                                | **Hashing**                                                                                                                                                                                                                                                             |
|--------------------------------------------------------------------------------------------------------------------------------------------------------|-----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|-------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| The process of converting data from one form to another (e.g. ASCII, Base64, Unicode). There is no cryptography involved and is completely reversible. | The process of transforming data with the use of a secret (key). Encryption is reversible by using decryption with the help of the key. Considered secure as long as the key is confidential. | Data is converted to a hash value using some hashing function; it is non-reversible. Given some data, along with the output of a hashing algorithm, it is possible to verify whether the data matches the original input data without needing to see the original data. |

### Suitability of these approaches for password management

* Encoding is not suitable for password management since the encoded data can be easily reversible and hence, it is not secure.
* Encryption is not a recommended approach as well, because the generated key can be lost - resulting in loss of security and confidentiality in the encryption process (especially if symmetric encryption is used).

> _Note:_ symmetric encryption is useful for encrypting data at rest. For example, AWS S3 encrypts data at rest, so even when the data is exposed, attackers cannot decrypt the data since the key is kept secure by AWS.
> Asymmetric encryption, which uses both public and private keys, is useful for encrypting data in transit.

* Hashing is a recommended approach as we cannot interpret the original input value just by looking at th output - because hashing is non-reversible.

> _Note:_ when we use a hash function to transform an input, using the same input will always generate the same hash (digest value).
> Hash functions will also output a consistent, fixed-length output (e.g. 256 bits for SHA-256).

#### Using hashing:

When a user registers with a password, the hashed password is stored in the database.
During login, the entered password is also hashed with the same hashing algorithm and compared against the hash in the database.

However, because hashing always results in _the same value_. Attackers can conduct brute force attacks or rainbow (dictionary) table attacks.
* In brute force attacks, attackers can check commonly used passwords and calculate their respective hash values, making it possible to match the hash value back to the user's hashed passwords.
* In rainbow table attacks, attackers maintain a table of commonly used passwords and their pre-calculated hash values.
